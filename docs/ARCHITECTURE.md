# Architecture
TypeScript workspace: apps/studio uses React and the Next.js App Router API through vinext, deployed as a dedicated Cloudflare Worker. packages/core defines Zod boundaries; packages/storage supplies browser and atomic local-file adapters. Browser records are local to the device and origin. Print coordinates use inches, converted to PDF points at export. Puzzle packages must remain independent of React and artwork services.

Server `/api/export` validates a bounded 2 MB input, regenerates authoritative puzzles, checks progression/rewards/approvals and returns a PDF/SVG handoff ZIP. All projects remain in browser local storage; the server does not retain user manuscripts. Client export adds 300 DPI canvas PNGs and finalizes manifest hashes. CLI export uses sharp and produces review packages under artifacts/enchanted-kingdom.

Production jobs use versioned Zod records in browser storage, deterministic page inputs, zero-cost SVG assets, output hashes, attempts and logs. Startup recovers interrupted running jobs as pending. Processing checks current page revision and approval before applying output. Missing/changed pages fail explicitly. Chapter/page metadata is separate from theme-independent puzzle mechanics.

Build 006 adds packages/editor: Zod canvas schemas, immutable history operations, print settings, grid snapping, monochrome SVG rendering and a shared SVG import boundary. packages/composer routes pages with editor state to the visual renderer; pages without it retain the legacy renderer. Browser drafts are keyed by adventure and page IDs. Canvas state and asset references travel in the existing project JSON and storage adapters.

Visual page PDFs/PNGs always use their saved trim/bleed/resolution. The Publishing profile continues applying to legacy pages. PDF fonts are loaded through the ASSETS binding, with fixed-weight Fredoka/Nunito print files. Browser PNG export embeds those fonts into a self-contained SVG before rasterization, then finalizes manifest hashes. History is excluded from export requests to avoid needless request growth; editable current layout and provenance remain in the package.

Export renderer adapters: packages/print/pipeline.ts owns the common validation, composition, PDF/ZIP and provenance work. export.ts injects server PDFKit; browser.ts lazily injects standalone browser PDFKit. Studio uses the server first, retries transient errors once, and falls back only for capacity/network errors. 4xx approval/validation failures remain terminal; the browser adapter independently re-runs the same mandatory checks. No separate geometry or publishing bypass exists.
